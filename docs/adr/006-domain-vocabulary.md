# ADR-006: 领域词汇约定

## 状态

已接受 (2026-08-09)

## 背景

系统中的核心概念在多处出现（代码、文档、前端、PPT、答辩），需要统一命名以避免歧义。老师特别指出「不要谈角色的事，把 Agent 那个角色一律转到属性上面」。

## 决策

| 概念 | 代码 | 文档/论文 | 前端 | PPT |
|---|---|---|---|---|
| 参与者 | `AgentLabel` | 智能体 (Agent) | Agent 节点 | 智能体 |
| 机密性维度 | `Clearance` / `Sensitivity` | 安全级别 | 机密级 (L0-L3) | 谁能看 |
| 完整性维度 | `Trust` | 完整性级别 | 完整度 (T0-T3) | 能不能信 |
| ALLOW | `ALLOW` | 允许 | 绿色✓ 放行 | 允许 |
| HIDE | `HIDE` | 隐藏 | 黄色 #var 遮蔽 | 隐藏 |
| CONFIRM | `CONFIRM` | 确认 | 蓝色 需确认 | 需人工确认 |
| DENY | `DENY` | 拒绝 | 红色✗ 阻断 | 拒绝 |
| LOMAC | LOMAC / low_watermark | LOMAC 低水位 | 水位变化 | 低水位标记 |
| 认知层 | `Layer.D/R/C` | 指令层/推理层/结论层 | D层/C层/R层 | 三层信息域 |

## 特别约定

- **不用角色语言描述行为**。说「L2 级智能体可以读 L2 及以下的记忆」，不说「分析师可以读情报员的记忆」。
- **属性语言替代**。「Planner 对 Intel 有 `ancestorof_intel` 属性」→ 策略串中出现的是属性，不是角色名。
- HIDE 和 CONFIRM 是独立概念，不说「HIDE 就是打码」「CONFIRM 就是弹窗确认」。HIDE = 结构上限制信息进入上下文，CONFIRM = 流程上暂停等待人工。

## 后果

- 文档和 PPT 必须使用属性语言而非角色语言
- 前端已有角色名称显示可保留，但加注属性标签
- 代码中的枚举名保持不变（重构成本高于收益）
