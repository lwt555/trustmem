# ADR-008: 标签签发与背书签名 — 信任权威九条原则

## 状态

已接受 (2026-08-15) · 待实现

## 背景

当前系统的两处信任来源是「软」的：

1. **标签自述**——`AgentLabel` 的密级 / 完整度 / 角色 / 工具集是构造时直接填写的字段，无签名、无来源。PDP 裁决时直接信任这些字段，无法区分「安全管理员签发」与「agent 自报」。
2. **背书门点按钮**——`core/upgrader.py` 的 TR13 已声明「人在环显式确认（密码学验签）」，但实现仍是「前端点批准 → T 直升 T3」。点按钮无法归因、可伪造、难审计。

一句话定位：**安全性不靠模板也不靠检测，靠「标签是签出来的、可信度只能签着升」。** 本 ADR 把这两处信任来源升级为密码学凭证，九条原则为最终规格。

## 决策

**原则 1 — 预置信任锚，含 anchor rollover。**
安全管理员（admin）的根公钥在系统部署时预置，是整条信任链的地基。agent、标签、背书人名单一律不得携带公钥。锚支持轮换（rollover）。

**原则 2 — 有效期以 epoch 表达，与吊销共用一把尺；epoch 作为显式裁决输入并记入审计 → PDP 保持纯函数可回放。**
不引入独立的时间戳有效期。有效期与吊销统一为 epoch：吊销 = 强制推进 epoch。PDP 裁决把 epoch 作为显式入参 `eval(..., epoch=now)`，不读墙钟，裁决结果连同所用 epoch 一起进审计，保证纯函数性与可回放。

**原则 3 — M-of-N 多重签名（非门限聚合），N 名单 admin 签发，跨链路、禁自背书、门限随目标等级浮动。**
背书采用 M-of-N 多重签名，不用门限聚合（BLS 单签名）——每个背书人独立签名、身份可审计。N 名授权背书人名单由 admin 签发。背书人须来自不同链路（跨链路），且不得在待背书内容的派生链内（禁自背书）。门限 M 随目标等级浮动：跳得越高，要求的签名人数越多（如 T1→T2 需 1-of-3，T1→T3 需 2-of-3）。

**原则 4 — 签绑定元组（明文哈希 + policy_hash + T_old→T_new + epoch + nonce + 域分隔），非密文、非单值。**
背书签名域是绑定元组，而非单个值、更非密文：
- `明文哈希`：证明「见过这份内容」（必须解密后对明文取哈希）
- `policy_hash`：绑定具体访问策略，防重放到别策略
- `T_old→T_new`：绑定具体信任跃迁，防用低阶背书去撬高阶
- `epoch`：绑定时间上下文，防旧背书重放
- `nonce`：每次背书新鲜，抗重放
- `域分隔`：与标签签发等其他签名类型隔离，防跨协议混淆

**原则 5 — T 只追加、单一写入路径、入口验签 —— 「只能签着升」落在代码结构上。**
完整性 T 是 append-only 结构，全系统只有**一个**写入口能让 T 上升，该入口处验签。因此「只能签着升」是结构性不变式，不是散落在各处的检查，不可绕过。

**原则 6 — 独立性由信任链根结构性判定，判定结果一并签名。**
背书人是否独立（不在待背书内容的 provenance 派生链内），从信任链根结构计算得出，不由背书人自报。判定结果本身一并签名，使其可审计。

**原则 7 — 背书可撤销，沿派生链级联降级，不追溯改写历史裁决。**
背书可撤销；撤销沿派生链级联——所有继承该背书可信度的下游内容一并降级。但历史裁决不改写：Merkle 树不可变，只改当前与未来的信任状态，不回滚已记录的决策。

**原则 8 — 任一前提缺失一律 fail-closed 不升。**
签名无效、元组不匹配、独立性不足、epoch 过期、门限不足——任一项缺失，默认拒绝，不升。

**原则 9 — 上述全部事件进同一棵 Merkle 树。**
标签签发、背书、撤销、PDP 裁决、独立性判定、锚轮换，全部事件进同一棵审计树，单一审计根。

## 实现要点

| 原则 | 落点 | 涉及代码 / 事件 |
|---|---|---|
| 1 信任锚 | admin 根公钥预置，锚带版本号；标签只存 `anchor_version` 指纹，不存公钥 | 新增锚管理；`SIGNKEY_BIND` 扩展 |
| 2 epoch | `pdp.eval(..., epoch=now)` 显式入参 + 审计；吊销 = 推进 epoch，与现有 `key.epoch < agent.epoch` 检查统一 | `core/pdp.py`、`core/session.py`、`core/crypto/engine.py` |
| 3 M-of-N | 背书人名单由 admin 签发（名单本身也是被签凭证）；每人独立签名不聚合 | `core/upgrader.py` + 新增 endorser 注册 |
| 4 绑定元组 | 固定签名域 + 域分隔串；验签时逐字段比对 | `core/crypto`（签名/验签） |
| 5 单一写路径 | T 升级只经一个函数，入口验签 | `core/upgrader.py`（TR13 点按钮 → 验签） |
| 6 独立性 | 从 provenance chain 结构计算，结果签名 | `core/upgrader.py`（TR14 抗 Sybil 升级为结构性判定） |
| 7 级联撤销 | 撤销沿派生链降级，历史不可变 | `core/merkle.py` + 撤销逻辑 |
| 8 fail-closed | 验签入口默认拒绝，缺前提不升 | 验签入口 |
| 9 单树 | 新增事件类型入 Merkle | `core/merkle.py` 扩展事件类型 |

需新增的 Merkle 事件类型（在现有 13 类基础上）：`LABEL_ISSUE`、`ENDORSE`、`ENDORSE_REVOKE`、`INDEPENDENCE`、`ANCHOR_ROLLOVER`。

## 后果

- 标签从「自述字段」变为「签名凭证」，PDP 每次裁决先验签，杜绝伪造标签。
- 背书门从「点按钮」变为「双人（M-of-N）签名 + 明文哈希绑定」，可归因、不可伪造、可审计。
- 与 `docs/TRUST_RULES.md` 的 TR11–TR14 同源：本 ADR 是 TR13/TR14 的密码学落地，TR1–TR10 的单调不增性质不变。

## 锚轮换规则（已定，采用①且劈成两问）

「验得出」与「授得权」必须分家，否则失陷轮换时「按记录时锚版本验签」恰好是攻击者想要的规则——拿泄露旧锚补签回溯标签，全部验签通过。

| 问题 | 规则 | 用途 |
|---|---|---|
| 这个签名确实是锚 A 产生的吗？ | 永远按 `anchor_fpr` 查历史锚集验签，永不失效 | 审计回放、取证 |
| 这个标签现在授权吗？ | 还需锚 A 在该 epoch 处于良好状态（未被标记失陷） | PDP 裁决 |

- 锚集只追加，每个锚带状态区间：`anchor { fpr: sha256(pubkey), valid_epochs: [e_in, e_out), status: OK | COMPROMISED_FROM(e_c) }`。fpr 用指纹不用递增整数，自证、防分叉混淆。
- `anchor_fpr` 写进标签**签名载荷内部**，不是签名旁的提示字段，否则存在跨锚降级混淆。
- 未知 fpr → 直接拒绝，禁止「逐个锚试一遍」（试锚是经典降级洞）。
- **计划轮换**：旧锚签新锚（rollover cert）进 Merkle 树，旧标签不需重签、自然到期；标签任务域绑定、编成结束失效，存活集小、重签成本近零。
- **失陷轮换**：旧锚签新锚路径断开（不能用失陷密钥签继任者），走离线 / M-of-N 管理员法定人数带外重建。写 `COMPROMISED_FROM(e_c)`：该锚签发且 `epoch ≥ e_c` 的标签一律作废、强制重签；`epoch < e_c` 仍授权有效。
- 整条证书链同规则：审查员密钥证书由根签，失陷点切断链条——`e_c` 之后的背书签名同样降级为「仅可验证、不再授权」，并沿派生链级联降级（接原则 7）。
